<objective>
Detect USB disconnection of the HackRF and surface the event through diagnostics without crashing the node.

Purpose: pyhackrf2 raises RuntimeError or OSError when the USB device is unplugged mid-stream. Currently these exceptions can bubble up uncaught from `_rx_callback` (called from the pyhackrf2 C thread) or from `stop_rx`/`start_rx` in the param worker thread. An uncaught exception in the USB thread causes pyhackrf2 to abort the stream silently; an uncaught exception in a ROS2 callback causes the executor to log an error but may leave the node in an indeterminate state.

The fix: a `_handle_usb_fault()` method that sets `_usb_fault = True` and `_usb_fault_time`, stops streaming state, and logs. Callers: `_rx_callback` error path and `_param_worker` error path. `_diagnostics_callback` checks the fault flag and escalates from WARN to ERROR over `DISCONNECT_ERROR_TIMEOUT` seconds.

Note: REL-02 (03-02) must run first because this plan adds USB fault handling to `_param_worker`, which 03-02 introduces.

Output:
- `DISCONNECT_ERROR_TIMEOUT = 2.0` module-level constant
- `_usb_fault: bool` and `_usb_fault_time: float` instance variables
- `_handle_usb_fault(source: str)` method
- `_rx_callback` wrapped to catch RuntimeError/OSError and call `_handle_usb_fault`
- `_param_worker` stop_rx/start_rx error paths extended to call `_handle_usb_fault`
- `_diagnostics_callback` WARN/ERROR escalation based on fault age
- `test/test_usb_disconnect.py` with source-level assertions
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pyhackrf2 USB C thread → _rx_callback | Untrusted: C thread may call with garbage data or raise on disconnect |
| _param_worker thread → _handle_usb_fault | Worker thread writes shared bool; CPython GIL makes bool write atomic |
| _diagnostics_callback → _usb_fault_time | Timer thread reads float written by USB/worker thread; atomic under GIL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Denial of Service | _rx_callback uncaught exception crashes USB thread | mitigate | Wrap entire _rx_callback body in try/except (RuntimeError, OSError); return False on exception so pyhackrf2 C layer sees clean return |
| T-03-03-02 | Denial of Service | _usb_fault stuck True after device re-plug | accept | Node must be lifecycle-restarted to re-open device; clear path is `ros2 lifecycle set /hackrf_node cleanup` then `configure` — by design |
| T-03-03-03 | Information Disclosure | usb_fault=true leaks device state on /diagnostics | accept | /diagnostics is on local ROS2 network; no PII; fault state is intentionally surfaced for operators |
| T-03-03-04 | Tampering | _usb_fault set spuriously on transient USB error | mitigate | DISCONNECT_ERROR_TIMEOUT=2.0 s gives WARN window; only escalates to ERROR if fault persists; operator can restart node cleanly |
</threat_model>
