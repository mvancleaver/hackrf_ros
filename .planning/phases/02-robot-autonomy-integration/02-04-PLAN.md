<!-- Cell value formula (D-12) -->
```python
def _power_to_cell(power_dbm: float) -> int:
    """Map dBm power to occupancy cell value [0, 100]."""
    return int(max(0, min(100, (power_dbm + 120.0) / 80.0 * 100.0)))
# -120 dBm → 0, -40 dBm → 100, -80 dBm → 50
```

<!-- EMA accumulation (D-12) -->
```python
# alpha=0.1 (configurable via ema_alpha parameter)
# cell_power[row, col] updated on each detection observation
cell_power[r, c] = (1 - alpha) * cell_power[r, c] + alpha * power_dbm
```

<!-- TF lookup pattern (Humble, same as 02-03) -->
```python
import tf2_ros
self._tf_buffer = tf2_ros.Buffer()
self._tf_listener = tf2_ros.TransformListener(self._tf_buffer, self)
try:
    t = self._tf_buffer.lookup_transform(
        self._grid_frame, 'base_link',
        rclpy.time.Time(), timeout=rclpy.duration.Duration(seconds=0.1))
    robot_x = t.transform.translation.x
    robot_y = t.transform.translation.y
except (tf2_ros.LookupException, tf2_ros.ExtrapolationException):
    return  # drop this update silently
```

    **_world_to_cell(wx, wy, origin_x, origin_y, resolution, nrows, ncols) → tuple[int,int] | None:**
    - col = int((wx - origin_x) / resolution)
    - row = int((wy - origin_y) / resolution)
    - Return (row, col) if 0 <= row < nrows and 0 <= col < ncols, else None

    **_detections_callback(msg: RFDetectionArray):**
    - Look up robot position via TF (base_link → grid_frame, timeout 0.1s)
      On exception: return (drop update, per D-14)
    - Compute grid origin (sliding window centered on robot):
      origin_x = robot_x - (self._grid_cols / 2) * self._grid_resolution
      origin_y = robot_y - (self._grid_rows / 2) * self._grid_resolution
    - Store self._origin_x, self._origin_y (used in _publish_grid)
    - For each detection in msg.detections:
      - cell = _world_to_cell(robot_x, robot_y, origin_x, origin_y, ...)
        (use robot position as the spatial anchor for now — the robot IS at the detection
        location since it has no bearing information; this is a deliberate simplification
        appropriate for a single-antenna system per Phase 2 scope)
      - Actually use the robot's world position as the grid cell target, since a single HackRF
        has no direction-of-arrival capability — we record "at this location, this power was seen"
      - If cell is None: skip
      - If not cell_observed[r, c]:
          cell_power[r, c] = detection.power_dbm  # first observation
          cell_observed[r, c] = True
        else:
          cell_power[r, c] = ((1.0 - alpha) * cell_power[r, c]
                               + alpha * detection.power_dbm)  # EMA
    - Store self._last_robot_x, self._last_robot_y for grid origin in publish

    **_publish_grid():**
    - Build OccupancyGrid msg (see interfaces block for field layout)
    - Use stored self._origin_x, self._origin_y (or 0,0 if no detection received yet)
    - data array: where cell_observed is True → _power_to_cell(cell_power[r,c])
                  where cell_observed is False → -1 (unknown)
    - Flatten row-major: data = grid_data.flatten().tolist()
    - Publish on self._grid_pub

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /hackrf/detections subscriber → grid | Detection messages from cfar_node (trusted process) |
| OccupancyGrid publisher → Nav2 | Grid data consumed by navigation costmap |
| TF buffer → grid origin | Robot pose from TF tree used to locate grid cells |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Tampering | Malicious RFDetectionArray with extreme power_dbm values | mitigate | _power_to_cell clamps to [0,100]; EMA smoothing limits rate of change; no buffer overflow possible |
| T-02-04-02 | Denial of Service | High-rate detections flooding grid accumulation callback | accept | RELIABLE QoS with depth=10 buffers bursts; accumulation is O(n_detections) per message; at 10 Hz detection rate and 20 detections/frame, negligible CPU |
| T-02-04-03 | Information Disclosure | OccupancyGrid encodes robot travel path implicitly | accept | Robot-internal topic; not published externally; Phase 4 can add topic encryption if needed |
| T-02-04-04 | Denial of Service | Grid memory: 50m x 50m @ 0.5m/cell = 100x100 = 10000 cells | accept | 10000 float32 cells = 40 KB; well within Jetson ARM64 memory budget |
| T-02-04-05 | Spoofing | TF tree poisoned with false robot position | accept | TF is an internal ROS2 topic; threat is outside Phase 2 scope; TF security is a system-level concern |
</threat_model>
