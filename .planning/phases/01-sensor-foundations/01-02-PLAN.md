<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ROS2 param → TF frame_id | User-supplied antenna_frame string becomes frame_id in published messages |
| ROS2 param → device config | Parameter values are applied to hardware (center_freq, gains) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | antenna_frame parameter | accept | Frame names are strings in TF tree; a wrong name produces no transform lookups (fail-safe: no injection risk) |
| T-02-02 | Denial | MultiThreadedExecutor + RLock | mitigate | Device lock (_device_lock RLock) already in place; executor thread pool cannot cause deadlock since lock is reentrant and not held across sleep |
| T-02-03 | Information Disclosure | /hackrf/spectrum BEST_EFFORT | accept | Spectrum data is observable RF environment — no PII or credentials in message fields |
| T-02-04 | Elevation of Privilege | scipy.fft replace | accept | Drop-in API; no new attack surface; scipy is a trusted PyPI package already in scientific Python stack |
</threat_model>
